# NileGov Stack Testing Strategy

This document outlines the testing framework and quality control strategy for the **NileGov Stack**. Every pull request and release is validated across five distinct verification tiers.

---

## The Testing Pyramid

```text
               /\
              /  \     Tier 5: Architecture Fitness Tests (AST)
             /    \    Tier 4: Restrictive Permission Tests (RBAC)
            /      \   Tier 3: Frappe Integration Tests (Database/API)
           /        \  Tier 2: Application Use Case Tests (Fakes/Ports)
          /__________\ Tier 1: Pure Domain Unit Tests (Independent of DB/Web)
```

---

## Five-Tier Verification Details

### Tier 1: Pure Domain Unit Tests (Independent)
* **Goal:** Verify business calculations, value object logic, and workflow state transitions without the overhead of a database connection or a running application framework.
* **Rules:** Must not import `frappe`, `sys`, or HTTP libraries. Must run within standard Python `unittest` or `pytest` in milliseconds.
* **Test Targets:**
  * NIN checksum validity (14 characters, specific letter positions).
  * Email and phone format structures.
  * Workflow state transitions (asserting exceptions when transitioning from `Draft` to `Under Review` directly, etc.).
  * SLA calculation logic.
  * Emission of domain events (e.g., asserting that transitioning status appends a new event payload to a local list).

### Tier 2: Application Use Case Tests
* **Goal:** Verify orchestration pipelines and application services using in-memory Fakes and Mock Adapters.
* **Rules:** Run independently of Frappe's test runner, using fake repositories (e.g., an in-memory dictionary acting as the service request store).
* **Test Targets:**
  * Submit Lost National ID request (verifying data propagates through to the fake repository).
  * Capture consent and run identity check.
  * Automatic assignment to the least-busy case officer.
  * Case notes additions and manual escalation.
  * Dashboard metrics calculation algorithms.

### Tier 3: Frappe Integration Tests
* **Goal:** Verify that NileGov custom DocTypes connect, migrate, and save correctly inside the Frappe Framework runtime.
* **Rules:** Run via the standard bench test utility: `bench run-tests --app nilegov_stack`. Requires a running database (MariaDB/Postgres).
* **Test Targets:**
  * Custom DocTypes (e.g. `Service Request`, `Consent Record`) persist and map accurately.
  * Database relationships (Link fields, Table fields) are correctly established.
  * Frappe Workflow status hooks invoke application services.
  * Database changes update monitoring metrics tables.

### Tier 4: Restrictive Permission Tests
* **Goal:** Validate role-based access control (RBAC) and least privilege settings.
* **Rules:** Executed via mock users and permission states in integration tests.
* **Test Targets:**
  * **Citizen Isolation:** Verify that Citizen A receives a 403 / Permission Error when requesting files or details of Citizen B.
  * **Officer Queue Isolation:** Enforce that a Case Officer cannot view or edit case notes of an unassigned request or requests assigned to other officers.
  * **Supervisor Authorization:** Validate that only Supervisors have write rights to reassign escalated files.
  * **Integration Log Security:** Unauthenticated users must be barred from calling simulated integration endpoints or viewing logs.
  * **Dashboard Read-Only:** Leadership dashboard endpoints must refuse write/update verbs.

### Tier 5: Architecture Fitness Tests (AST)
* **Goal:** Enforce decoupling code policies automatically.
* **Implementation:** A static analysis test script (e.g., using `ast` parsing or simple directory scans) run inside the test suite.
* **Rules:** The build will fail if any of the following are detected:
  * Any python file within `domain/` contains `import frappe` or `from frappe...`.
  * Any python file within `domain/` contains raw SQL queries or database driver imports.
  * Any python file within `domain/` contains HTTP libraries (like `requests` or `urllib`).
  * Any code contains prohibited prompt residue strings:
    * `"generated by ChatGPT"`
    * `"generated by Claude"`
    * `"AI-generated"`
  * Any claim of live external registry connectivity (e.g. "live NIRA access") appears in documentation or code.

## Test Execution Commands

### Running Unit & Use Case Tests
To run independent domain tests (Tier 1 & 2):
```bash
pytest nilegov_stack/tests/unit
```

### Running Frappe Integration & Permission Tests
To run database-dependent tests (Tier 3 & 4):
```bash
bench --site nilegov.local run-tests --app nilegov_stack
```

### Running Architecture Fitness Gate
To run static analysis checks (Tier 5):
```bash
python nilegov_stack/tests/architecture/test_fitness.py
```
